고해상도 GPose 스크린샷은 보기에는 선명하지만, 브라우저 편집기에서는 파일 크기와 메모리를 함께 사용합니다. XIV Frame은 파일을 서버로 올려 처리하는 서비스가 아니기 때문에, 업로드한 파일을 현재 기기의 브라우저가 읽고 캔버스와 배경 제거 기능을 실행합니다. 따라서 용량 제한은 단순한 숫자보다 **모바일에서 멈추지 않고 작업을 끝내기 위한 안전선**에 가깝습니다.

## 먼저 알아둘 제한

- 사진과 합성 이미지 파일은 한 장당 **50MB 이하**여야 합니다.
- 사진은 최대 16장까지 한 캔버스에 추가할 수 있습니다. 3×3·4×4 격자 템플릿은 각각 9장·16장의 사진을 사용합니다.
- 큰 이미지의 긴 변은 편집에 맞도록 브라우저에서 최대 4096px 범위로 최적화될 수 있습니다.
- 합성 이미지의 배경 제거는 기기에서 모델을 실행하므로 사진 편집보다 메모리와 시간이 더 필요합니다.
- 제한을 넘는 파일은 브라우저 최적화 단계까지 도달하지 못하므로, 먼저 파일 자체의 크기를 줄여야 합니다.

이 제한은 원본을 서버에 보관하기 위한 제한이 아닙니다. 현재 편집 결과를 빠르게 만들고, 브라우저 탭 하나가 기기의 메모리를 과도하게 점유하지 않도록 두는 제한입니다.

## 1. 업로드 전에 파일을 확인합니다

1. 파일의 확장자보다 실제 형식을 확인합니다. PNG, JPG, WebP처럼 브라우저에서 읽을 수 있는 이미지인지 먼저 봅니다.
2. 파일 크기가 50MB보다 큰지 확인합니다. 파일 이름만 바꾸어 확장자를 바꾸는 것은 용량이나 형식을 바꾸지 않습니다.
3. 같은 장면을 여러 장 사용할 때는 원본을 모두 올리기 전에 실제로 필요한 컷만 고릅니다. 최대 16장까지 사용할 수 있어도 각 이미지가 크면 전체 작업 부담이 커집니다.
4. 배경 제거가 필요한 이미지는 먼저 한 장만 올려 테스트합니다. 결과가 괜찮은 것을 확인한 뒤 다음 요소를 추가하면 실패 원인을 찾기 쉽습니다.

## 2. 사진 형식과 화질을 선택합니다

사진 자체에 투명 영역이 필요하지 않다면 JPG나 WebP가 PNG보다 가벼운 경우가 많습니다. 반대로 투명 배경을 유지해야 하는 합성 요소나 로고는 PNG가 적합합니다. 파일 형식은 무조건 하나가 더 좋은 것이 아니라, **사진인지 투명 요소인지**에 따라 선택하세요.

스크린샷을 줄일 때는 다음 순서가 안전합니다.

1. 먼저 긴 변의 크기를 확인합니다. 게시할 화면이나 SNS에서 실제로 필요한 크기보다 지나치게 큰 원본이면 긴 변을 줄입니다.
2. JPG/WebP로 바꿀 때는 품질을 한 번에 최저로 낮추지 말고, 글자·얼굴·가는 선이 무너지지 않는 지점을 확인합니다.
3. PNG의 투명 영역이나 UI 글자가 중요한 파일은 형식을 바꾸기 전에 가장자리와 작은 글자를 확인합니다.
4. 줄인 파일을 저장한 뒤 파일 크기를 다시 확인하고 XIV Frame에서 선택합니다.

XIV Frame이 업로드 후 큰 이미지의 편집용 크기를 자동으로 조정하더라도, 50MB를 넘은 파일을 먼저 받을 수 있는 것은 아닙니다. 자동 최적화는 제한을 통과한 파일을 편집하기 좋게 만드는 단계입니다.

## 3. 브라우저에서 작업할 때 메모리를 아낍니다

1. 필요하지 않은 편집 탭과 대용량 이미지 탭을 닫습니다.
2. 사진을 한 번에 4장 넣기보다 대표 컷을 먼저 배치하고, 레이아웃이 정해진 뒤 나머지를 추가합니다.
3. 합성 배경 제거 모델이 준비되는 동안에는 새로고침하지 않습니다. 첫 실행은 모델 다운로드·초기화 때문에 일반적인 사진 업로드보다 오래 걸릴 수 있습니다.
4. 모바일에서는 배경 제거와 브러시 보정을 한 장씩 끝낸 뒤 다음 이미지로 넘어갑니다.
5. 브라우저가 탭을 종료하거나 결과가 비어 보이면 같은 파일을 다시 선택하기 전에 기기의 여유 저장공간과 메모리를 확인합니다.

## 4. 품질을 확인하는 방법

화면 확대 배율은 편집 화면을 보기 위한 값이고 저장 파일의 실제 해상도를 직접 올리는 기능이 아닙니다. 저장 전에는 다음 세 가지 배율로 확인하는 것이 좋습니다.

- **작은 미리보기**: 전체 균형, 사진 순서, 여백, 텍스트가 한쪽으로 쏠리지 않았는지 확인합니다.
- **100% 근처**: 얼굴, 가는 선, 합성 가장자리, 저작권 문구가 깨지거나 겹치지 않는지 확인합니다.
- **확대 확인**: 배경 제거 경계와 브러시 보정 흔적을 확인합니다. 확인이 끝나면 전체 화면으로 돌아가 최종 균형을 다시 봅니다.

500%로 합성 요소를 키우는 것은 캔버스 안에서 위치를 맞추기 위한 조정입니다. 원본에 없는 디테일을 새로 만들어 주지는 않으므로, 작은 원본을 지나치게 확대하면 가장자리가 흐려질 수 있습니다.

## 5. 업로드되지 않을 때의 진단 순서

1. 파일이 50MB 이하인지 확인합니다.
2. PNG, JPG, WebP 중 하나로 다시 저장하고 파일을 새로 선택합니다.
3. 같은 파일이 아니라 작은 복사본으로 업로드해 파일 자체의 문제인지 확인합니다.
4. 다른 이미지 하나가 정상적으로 보이는지 확인합니다. 다른 파일도 실패하면 브라우저나 기기 상태를 먼저 의심합니다.
5. 페이지를 새로고침하기 전에 필요한 설정값을 기억합니다. 편집 설정은 로컬에 남을 수 있지만, 업로드한 사진 파일 자체는 새로 선택해야 합니다.
6. 모바일에서 배경 제거만 실패한다면 사진 업로드와 자동 제거를 분리해 테스트합니다. 모델 준비 중인지, 파일 크기·형식 문제인지 오류 메시지를 기준으로 구분합니다.

## 저장 파일을 가볍게 만드는 기준

완성된 PNG가 크다면 원본을 무조건 낮추기보다 결과의 목적부터 정합니다. SNS 미리보기라면 긴 변을 게시 서비스 기준에 맞추고, 인쇄나 보관용이라면 원본 프로젝트와 게시용 사본을 따로 저장하세요. XIV Frame은 프로젝트 파일을 서버에 보관하지 않으므로, 다시 편집할 가능성이 있는 원본과 최종 PNG를 같은 폴더에 보관하는 것이 안전합니다.

## 업로드 전 체크리스트

- 파일이 50MB 이하인가
- 필요한 사진만 선택했는가. 3×3·4×4 격자는 각각 9장·16장을 채웠는가
- 투명 요소는 PNG, 일반 사진은 필요한 경우 JPG/WebP로 준비했는가
- 모바일에서 메모리가 부족해질 만큼 여러 대용량 파일을 동시에 처리하고 있지 않은가
- 저장 전 100% 미리보기에서 작은 글자와 합성 경계를 확인했는가

용량 제한을 무작정 없애면 모든 기기에서 더 편해지는 것이 아니라, 모바일 브라우저가 탭을 종료하거나 배경 제거가 중단될 가능성이 커집니다. 현재 구조에서는 제한 안에서 파일을 준비하고, 브라우저 자동 최적화가 작동할 수 있도록 입력 파일을 정리하는 것이 가장 예측 가능한 방법입니다.
